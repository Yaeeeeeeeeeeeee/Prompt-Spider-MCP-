# Dashboard validation

Implemented session listing/filtering, snapshot and record reads, original MIT spider renderer, actual progress metadata, read-only historical replay with backward seek and local playback, merged MCP/V1 listing with 404 compatibility, optional legacy history, and explicit loading/empty/offline/authentication states.

`node tests/ui-dashboard.test.js`: 5 tests passed, 0 failed. Tests exercise source/project identity isolation, MCP context versus V1 filters, animation freeze states, real upstream replay reconstruction across status updates/completion/backward seek, and credential/rendering constraints. `node --check web/app.js` passed. These tests do not establish browser layout/accessibility, network reconnect timing or actual deployed authorization; integration/browser validation is reported separately by the parent task.

The Node environment wraps `node --test` in a way that hides individual failures; direct `node tests/ui-dashboard.test.js` supplies the full Node TAP results and is the recorded command. No backend or production records were changed by this UI subtask. No synthetic activity is shipped in dashboard assets; the replay unit test creates an ephemeral in-memory fixture only.

## Real browser verification

`npm run build` followed by `node tests/ui-browser.mjs` passed **21 browser checks** using real system Chromium (`/usr/bin/chromium`) through Playwright 1.62.1 and a disposable local Miniflare Worker with D1 migrations. No route mocks were used: MCP tools created a simulated session and updated/completed its event, and the real ingest endpoint accepted explicitly simulated Windows/cloud run records. Checks covered merged listings, explicit SIMULATED badges on all seeded MCP/V1 cards and selected session metadata, source filters, credential input clearing, full snapshot/replay completion, slider seeking, Jump to latest, playback advancement, actual completed-event counts, original canvas pixels, mobile viewport without horizontal overflow, offline/reconnect, logout DOM clearing, invalid-reader rejection, empty persistent storage, no credential URLs, no JavaScript errors, and no CSP violations. Screenshots: `.build/dashboard-browser.png` and `.build/dashboard-browser-mobile.png` (generated artifact, not committed).

The first browser run exposed a display bug where connection status `inactive` obscured upstream `completed`; the dashboard now substitutes connection status only for disconnected/timed-out sessions and preserves upstream terminal status. The complete browser check passed after this fix. Run `npm run test:browser` when the root package script is installed, or build then run the test file directly. Override `PLAYWRIGHT_CHROMIUM_EXECUTABLE` for another Chromium path. The test never accesses production; its records are ephemeral and explicitly simulated. Native Windows Hook execution, production connectivity and assistive-technology behavior remain outside these browser checks.
