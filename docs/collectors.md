# Optional event collectors

The delivered MCP is the independent remote Worker `/mcp` endpoint; see [MCP setup](mcp.md). Installing Windows hooks is optional and is not required to use its eleven tools. The existing `prompt-spider-api` service remains separate.

Both collectors emit V1 events. Explicitly set `SPIDER_ENDPOINT` to the **new Worker's** `https://HOST/api/events`; no endpoint is selected by default. Never point these V1 collectors at the old legacy service unless it has separately gained V1 support. Configure `SPIDER_WINDOWS_TOKEN` for Windows and `SPIDER_CLOUD_TOKEN` for cloud reporting using private environment settings. `--check-token` reports only present/missing. Never place token values in configuration committed to Git or shell history.

Windows: run `python tools/windows-hooks/install_windows.py` on Windows after reviewing its source. It preserves existing handler indexes, backs up original bytes, leaves config.toml unchanged, and does not grant hook trust. Review new hooks through Codex. The installer rejects paths containing shell expansion characters. The Linux tests verify generated command strings and merge behavior; they do not verify Windows execution or registry access.

Git roots are found by walking resolved ancestors to the nearest `.git` directory or file, including worktree/submodule markers. The collector does not execute Git or read a marker's target. Non-repositories use cwd. Project/session identifiers are HMACs using a local random key under `SPIDER_STATE_DIR` (default `~/.prompt-spider`); independent machines therefore do not automatically share project identity. No full paths, project names, prompts, commands, or transcripts enter payloads. A missing session ID gives each event a fresh run ID.

Cloud: `collectors/cloud/AGENTS.snippet.md` is explicit opt-in project guidance. It is not a global cloud hook. Example: `python collectors/cloud/report.py task_started --run-file /tmp/spider-unique-task.run --project .`. Reuse that file for heartbeat and an explicit task_completed/task_failed/task_cancelled event; choose a fresh file for each independent task. `--dry-run` performs no network request but creates local identity/run state. Lifecycle/model/tool events never establish task success; task completion needs an explicit report.

Delivery uses HTTPS, rejects redirects and URL credentials/query/fragment, applies a 1.2 second socket timeout, and queues an event before trying delivery. HTTP 202 removes it; failure retains the same event ID for `--flush` (at most ten files by default, no sleeps). Hook timeout is three seconds; filesystem operations and socket timeout do not constitute an absolute wall-clock guarantee. Queue storage is durable but unbounded: monitor or remove retained events when abandoning reporting. Concurrency may send duplicates, which backend event-ID deduplication handles. No periodic heartbeat or retry daemon is installed.

Run `python -m unittest discover -s tools/windows-hooks -v` and `python -m unittest discover -s collectors/cloud -v`. Tests use temporary state and mocked transport, never production writes. Real Windows shell/trust and real cloud task instrumentation still require deployment-specific checks.
