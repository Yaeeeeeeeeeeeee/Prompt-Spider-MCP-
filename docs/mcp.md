# Remote MCP

The Worker serves real MCP Streamable HTTP at `/mcp` using the official `@modelcontextprotocol/server` 2.3.1 SDK. Configure a remote MCP client with the deployed HTTPS URL and an `Authorization: Bearer <MCP_AUTH_TOKEN>` header. Keep this secret independent of all browser/event write/read tokens. Tokens never belong in URLs. The transport is stateless: initialize normally, then make requests without a transport session ID. Application sessions live in D1 across requests and Worker restarts.

The implementation retains the 11 upstream tools, three resources (`spider://guide`, `spider://config`, `spider://replay-format`), and `spider_report_task` prompt from MIT upstream revision `24a5db96fff2579baaa6fefce7d7051a929a8d57`. Session validation, replay reconstruction, aggregation, completion and playback use the original pure `SessionStore`, configuration and replay modules under `vendor/prompt-spider-ui/lib`. Configure and playback remain upstream-compatible, including upstream configure behavior for imported sessions.

By default event IDs and context `project_id`, `run_id` and `node_id` values are deterministic SHA-256 opaque identifiers and labels become `Task <hash-prefix>`. Reuse the original producer ID on updates; hashing the same original input preserves identity and task counts. Context `source` and `simulated` retain their declared values. Custom title, subtitle, model name and route label input is rejected. Explicit `MCP_ALLOW_PUBLIC_LABELS=true` permits public-safe labels, IDs, configuration text, export filenames and project names. Prompts, word mode, details and arbitrary timestamps remain disabled. This is a data minimization boundary, not a secret detector: callers must never submit credentials, command output, code or private reasoning. The reporting prompt echoes its task argument to the requesting MCP client, without persistence.

Cloud limits are 20 open sessions, 1,000 unique tasks, 700 KiB update history, and 900 KiB serialized state/artifact. Limits reject a whole operation without truncating history. D1 state uses optimistic compare-and-swap with up to five retries; concurrent mutations cannot overwrite one another silently. Absolute epoch anchors preserve elapsed and playback time across isolates. Closing hides the session but retains the row and its history for an operator-controlled retention policy. There is no automatic deletion or retention expiry; operators must manage this. Closed sessions are unavailable to tools.

`spider_export_session` returns a portable replay artifact with an authenticated `/mcp/artifacts/<id>` download URL, filename and format. It does not write a local file. Download requires the MCP authorization header. `spider_import_session` accepts one inline record or an artifact filename. Default imports accept cloud-redacted records only; custom text imports require the explicit public-label opt-in. All replay validation still runs through the upstream validator. Default export filenames are opaque hashes ending in `.json`, including caller-supplied filenames. Import by the actual returned `filename`, not the original requested name. Filenames cannot overwrite an existing artifact. Public-label mode permits simple `.json` basenames.

`spider_export_project` returns `prompt-spider-project-files/v1`, a JSON object with `name` and a `files` map. By default the project name is hashed, and its artifact filename uses that hash. An existing lowercase 64-hex project name is preserved to allow reuse without double hashing. The map contains original immutable upstream application/library/server/package/license sources, generated project configuration, optional MCP sources (default true), and optional recording (default false). It is a portable editable source artifact, not a ZIP or a filesystem directory. Unpack entries into a new directory preserving relative paths, then run `node server.mjs`. Install MCP dependencies separately if included. No deployment environment, credentials, browser secrets, Cloudflare settings, or dependencies are included. The size limit can reject a large recording/project combination.

The preview URL uses `/?session=<id>` with no credential. Browser access remains governed by the separate browser authorization policy. The MCP session list and the Windows hook event store are distinct data sources; this service does not automatically instrument tools or hook remote sessions into Windows.

`spider_create_session` also accepts an optional `context` object: `source` (`windows` or `cloud`), `project_id`, `run_id`, `node_id` (producer IDs of 1–80 letters, digits, `_` or `-`, hashed before storage by default), and `simulated` (boolean). Session ID arguments must be actual UUIDs returned by create/import. Context is persisted separately from upstream replay data and remains attached across clients. Source defaults to `unknown`; the service never guesses a producer from network origin. Summaries expose `context`, declared `source`, original upstream `session_kind` (`agent` or `replay`), `last_received_at` (server receive time), and `connection_status`. Live sessions become `disconnected` after 60 seconds without an accepted mutation, and `timed_out` after five minutes. Terminal sessions are `inactive`. These derived connection values never complete a live session or claim success. Playback mutations count as server activity; reads do not refresh activity.

The Worker verifies either its static MCP credential or configured OAuth access token before passing `{authenticated:true}` to `handleMcp`. Calling that function directly without this option retains its static-token authentication check. This trust option is an internal routing contract, never a request parameter. Tool failures return fixed safe validation messages or a generic failure message; raw database exceptions and paths are not sent to clients.

## Client connection after actual deployment

Codex CLI supports a remote Streamable HTTP registration (checked with this environment's `codex mcp add --help`):

```sh
codex mcp add prompt-spider-cloud --url https://YOUR-DEPLOYED-HOST/mcp --bearer-token-env-var MCP_AUTH_TOKEN
```

Replace the host with the real deployed endpoint, and securely configure the independent MCP token in the CLI process environment. Do not put its value in the command, URL, repository or chat. Adding a new MCP registration is additive; inspect an existing registration with the same name before replacing it. This command has not been executed against a production endpoint here.

For ChatGPT, use the actual deployed `/mcp` URL in an account/workspace that supports remote MCP connectors and choose OAuth. Configure the exact callback supplied by that product before authorization; approve in the Worker's password form. The live account login and callback have not been tested.

Codex Web/cloud tasks also require the product to support and expose the remote connector to that task. A `.codex/config.toml` file, environment variable, Skill or AGENTS instruction cannot by itself inject a new tool into the platform's available-tool list. No global connector or automatic activation across all cloud projects is claimed. Where the platform does not provide the MCP connection, the optional explicitly authorized HTTPS reporter is a separate best-effort fallback, not a real MCP-tool invocation.
